## 3. Delivery lifecycle (what the code does)

```
Runner loop (signal ctx)                      every 500 ms, at once if the last claim filled every free slot
  free = WORKER_CONCURRENCY - inFlight;  if free == 0 -> wait for a slot (or ctx done)
  out = ClaimDueDeliveries.Execute(ctx, {Limit: free})
      now = clock.Now(); lease = {Token: ids.New("lse_"), ExpiresAt: now + WORKER_LEASE_DURATION}
      ds  = DeliveryQueue.ClaimDue(ctx, now, free, lease)             -- 1 statement, autocommit
      tg  = EndpointCatalog.GetTargets(ctx, distinct endpoint IDs)    -- 1 query (adapter -> endpoint)
      pl  = MessageCatalog.GetPayloads(ctx, distinct message IDs)     -- 1 query (adapter -> message)
      -> Jobs (delivery + target + payload); Skipped (target or payload missing/unreadable)
  for each job: inFlight++, group.Go(AttemptDelivery.Execute(drainCtx, job))
AttemptDelivery (drain ctx)
  target disabled -> outcome endpoint_disabled, duration 0, NO HTTP
  else  started = clock.Now(); req = SignedRequest(job, started.Unix()); outcome, err = Sender.Send(ctx, req)
        err is ErrSendAborted (drain deadline) -> return it, record nothing (lease expiry recovers)
        duration = clock.Now() - started
  next, attempt = job.Delivery.ApplyOutcome(result, retryPlanner, clock.Now())
  TxManager.WithinTx(WithoutCancel(ctx) + 3 s):
      DeliveryQueue.Complete(next, job.Lease.Token)   -- fenced UPDATE first; 0 rows -> ErrLeaseLost
      AttemptRepository.Create(attempt)
```

### 3.1 State machine for this story

```
pending (attempt_count = n, next_attempt_at = due)
  --claim-->  pending (next_attempt_at = now + lease, lease_token = t)
  --2xx-->    succeeded (attempt_count = n+1, next_attempt_at = NULL, lease_token = NULL, last_attempt_at = started)
  --fail-->   failed    (same columns), or pending with next_attempt_at = retry time (US-005 only)
```

`Delivery.ApplyOutcome(r AttemptResult, p RetryPlanner, now time.Time) (Delivery, Attempt)` is the
one place these rules live. It is pure and table-tested:

| Outcome | Trigger | `RetryPlanner.Next` | Next state |
|---|---|---|---|
| status 200-299 | any | not called | `succeeded`, `next_attempt_at = nil` |
| `destination_blocked` or `endpoint_disabled` | any | **not called** | `failed`, `next_attempt_at = nil` (terminal) |
| other failure (non-2xx incl. 1xx/3xx/4xx/5xx, `timeout`, `dns_error`, `connection_error`) | `manual` | not called | `failed` (US-007 rule, free to have now) |
| other failure | `automatic` | returns `(_, false)` | `failed` |
| other failure | `automatic` | returns `(t, true)` | `pending`, `next_attempt_at = t` (exercised by a fake planner now; US-005 wires the real one) |

Every row also: `attempt_count = n+1`, `last_attempt_at = r.StartedAt`, `lease = zero`, and an
`Attempt{Number: n+1, Trigger: d.Trigger, ...}`.

US-004 wires `entity.NoRetry{}` (always `(time.Time{}, false)`), which satisfies "a failed first
attempt may simply be marked failed". US-005 adds `entity.BackoffSchedule` and a `Jitter` port and
changes only `wire/dispatch.go`. **No schema change and no signature change in US-005.**

**`ClaimDueDeliveries`** (`claim_due_deliveries.go`, internal, worker):


Private helpers: `distinctEndpointIDs`, `distinctMessageIDs` (a set, one flat loop each), `assemble`

guard clauses, so there are no nested ifs).

| Case | Expect |
|---|---|
| `Limit <= 0` | no calls, empty output |
| queue returns 0 rows | catalogs **not** called |
| 3 deliveries, 2 endpoints, 3 messages | `GetTargets` called once with 2 distinct IDs, `GetPayloads` once with 3; 3 jobs carrying the lease token |
| lease | token = `ids.New("lse_")`, `ExpiresAt = now + lease`, passed to `ClaimDue` with `now` and `limit` |
| endpoint missing from lookup | `Skipped{reason: target_missing}`, the other jobs still returned |
| endpoint in `Unreadable` | `Skipped{reason: secret_unreadable}` |
| payload missing | `Skipped{reason: payload_missing}` |
| `ClaimDue` / `GetTargets` / `GetPayloads` fails | wrapped error returned (claimed rows keep their lease and are retried after expiry) |

Skipped rows are left leased on purpose: they come back after the lease, and the runner logs them at
`error`. They cannot occur in a healthy system (composite FKs, no deletes in MVP), except for a
botched `SECRET_ENCRYPTION_KEY` rotation, where retrying after an operator fix is the right behaviour.

| Case | Expect |
|---|---|
| target disabled | `Sender.Send` **not called**; attempt `Err = endpoint_disabled`, `StatusCode = 0`, duration 0; delivery `failed`; completed with the job's lease token |
| 2xx | delivery `succeeded`, attempt status 200, body and truncation copied, `Number = attempt_count+1`, `Trigger` copied, ID prefix `att_` |
| headers and signature | the fake sender captures the request: `WebhookID = message ID`, `Timestamp = started.Unix()`, `Body` is the same bytes, `Signature == entity.Sign(key, id, ts, body)` |

| `destination_blocked` with a fake planner that would retry | `failed`, planner not called |
| retryable failure with a fake planner returning `(t, true)` | `pending`, `next_attempt_at = t` (US-005 readiness) |
| `Send` returns `ErrSendAborted` | error returned, `WithinTx` **not called** |
| `Complete` returns `ErrLeaseLost` | error is `ErrLeaseLost`, `Attempts.Create` **not called** (fake tx records calls in order) |
| `Attempts.Create` fails | wrapped error (the real tx rolls back the delivery update) |

**Integration tests** (`-tags integration`, real migrations; seed projects, endpoints, messages and deliveries
with direct SQL, never by importing another module):
- **Disjoint claims:** 200 due rows; two goroutines on two separate pools each call `ClaimDue(limit 50)` in a loop
  until empty. The union is 200, the intersection is empty.
- **SKIP LOCKED does not block:** open a tx that holds `FOR UPDATE` on 1 row; `ClaimDue` returns the others at once (< 1 s) and not that one.
- **Not due / terminal:** a row with `next_attempt_at` in the future, and `succeeded`/`failed` rows, are never claimed.
- **Order:** the oldest `next_attempt_at` is claimed first with `limit 1`.
- **Lease expiry (SIGKILL in-process):** claim at `t0` with a 30 s lease and never complete. `ClaimDue(now = t0 + 30s - 1µs)` → nothing; `ClaimDue(now = t0 + 30s)` → the row, with a new token.
- **Fencing:** claim (token A), let it expire, reclaim (token B). `Complete(token A)` → `ErrLeaseLost` and **no attempt row** (run it through the real `TxManager`); `Complete(token B)` succeeds.
- **Attempt CHECKs:** a status and an error together, neither, a 4097-byte body, or a body without a status are all rejected; a duplicate `(delivery_id, attempt_number)` is rejected.
- **Composite FK:** an attempt pairing project A's delivery with project B fails.
- **Migration:** `migrations/attempts_migration_integration_test.go`: up to 5, down to 4 (table gone, 0004 tables and data intact), up to 5, on a database that has deliveries.

### Step 5: `library/netguard` dialer + `dispatch/data/webhookhttp` sender

**`library/netguard/dialer.go`** (tests first: `dialer_test.go`, fake resolver from `policy_test.go`):
- `var ErrDestinationBlocked = errors.New("netguard: destination blocked")`.
- `type DialFunc func(ctx context.Context, network, address string) (net.Conn, error)`.
- `(p *Policy) GuardedDial() DialFunc`. Development: a plain `net.Dialer` (no IP checks, so compose works).
  Production: split host and port; an IP literal is checked directly; otherwise `Resolver.LookupNetIP(ctx, "ip", host)`.
  A resolver error is returned **wrapped with `%w`**, so `*net.DNSError` survives. If **any** address is blocked
  (`checkAddr`, the registration rule), return `ErrDestinationBlocked` and open no socket. Otherwise dial the vetted
  addresses in order (`net.JoinHostPort(addr.String(), port)`) with a `net.Dialer{Control: p.controlCheck}` until one
  connects. `controlCheck` parses the socket address and returns `ErrDestinationBlocked` if it is blocked (defense in
  depth: "the IP we check is the IP we dial").
- `(p *Policy) AllowlistedDial() DialFunc`: dials only when `host:port` equals an allowlist entry's host and port,
  without IP checks (the demo receiver can be private, e.g. `api:8080`). Anything else → `ErrDestinationBlocked`.
- `(p *Policy) IsAllowlisted(rawURL string) bool`: exported wrapper over `matchesAllowlist` (scheme, host, port, path prefix, dot segments).
- Tests: production + fake resolver `rebind.example → 127.0.0.1` pointing at a counting `net.Listener` → `ErrDestinationBlocked` and **0 accepts**; `169.254.169.254`, `::ffff:10.0.0.1`, mixed public/private → blocked; NX host → `errors.As(*net.DNSError)`; public answer → dials it; development → loopback allowed; allowlisted dial accepts only the configured host:port.

Small consumer-side interfaces in `runner.go`: `claimer{Execute(ctx, usecase.ClaimDueDeliveriesInput) (usecase.ClaimDueDeliveriesOutput, error)}`,

```go
type Config struct {
    Concurrency     int           // WORKER_CONCURRENCY (16)
    PollInterval    time.Duration // WORKER_POLL_INTERVAL (500ms)
    ShutdownTimeout time.Duration // WORKER_SHUTDOWN_TIMEOUT (25s)
}
func NewRunner(c claimer, a attempter, cfg Config, log *slog.Logger, hb *Heartbeat) *Runner
func (r *Runner) Run(ctx context.Context) error   // returns nil on graceful shutdown
```

- `runner.go`, `Run`: `drainCtx, cancelDrain := context.WithCancel(context.WithoutCancel(ctx))`; an
  `errgroup.Group` with `SetLimit(Concurrency)` (**not** `WithContext`: one failed job must not cancel its siblings;
  job funcs always return nil and log at the boundary); `r.loop(ctx, drainCtx, &g)`; once ctx is done:
  log `draining` with `in_flight`, `stop := time.AfterFunc(ShutdownTimeout, cancelDrain)`, `g.Wait()`, `stop.Stop()`,
  log `drained` or `drain deadline reached, leases will expire`, return nil.
- `loop.go`: one iteration = `free := Concurrency - inFlight.Load()`; `free == 0` → wait on `slotFreed` (chan, cap 1,
  non-blocking send from each job's defer) or ctx; claim; on error, `backoff.next()` and wait; on success, `backoff.reset()`,
  `hb.Beat(now)`, start jobs, log skipped; then **re-claim at once if `len(jobs) == free`**, else wait `PollInterval` (or ctx).
  Each wait is a `select` in its own helper, so no nesting exceeds one level.
- Each job: `inFlight.Add(1)`, `g.Go(func() error { defer done(); r.runJob(drainCtx, job); return nil })`. `runJob` recovers a
  panic (logs it at `error`, the lease recovers the row) and writes the attempt log line (`log.go`).
- `backoff.go`: DB errors back off 100 ms, doubling, capped at 5 s; reset after a successful claim.
- `heartbeat.go`: `Heartbeat{last atomic.Int64}`; `Beat(t)`; `Ping(ctx) error` returns an error when the last beat is
  older than `30s` (the worker `/healthz` → 503). It needs a clock: `NewHeartbeat(now func() time.Time, maxAge time.Duration)`.
- `log.go`: one line per attempt, fields in section 10. `ErrLeaseLost` → `warn` with `lease_lost=true`; `ErrSendAborted` → `info` `aborted_by_shutdown`.

Runner tests (fake claimer/attempter with channels, short intervals):
- claims only free slots: concurrency 4, the first claim returns 4 jobs and the attempter blocks → the claimer is **not called again** until a slot frees, then it is asked for `Limit = 1`;
- a full batch triggers an immediate re-claim (no poll wait); a short batch waits the poll interval;
- claim errors back off (100, 200, 400 ms … ≤ 5 s) and the loop keeps running; success resets;
- **cancel ctx: no `claimer.Execute` after cancel; in-flight attempts see a live context; `Run` returns nil after they finish**;
- **drain deadline:** attempter blocks forever, `ShutdownTimeout = 50ms` → its ctx is cancelled at ~50 ms and `Run` returns nil;
- a panicking attempter does not kill the runner; other jobs still complete;
- the heartbeat beats on every successful claim and `Ping` fails when stale.

## 5. Migration 0005 (`backend/migrations/0005_attempts.{up,down}.sql`)

The `deliveries` table from 0004 already has everything US-004/005/007 need (`attempt_count`,
`next_attempt_at` as due time and lease expiry, `lease_token`, `last_attempt_at`, `trigger`). **No
change to `deliveries`.** 0005 only adds `attempts`, owned by `dispatch`.

**Up**

```sql
-- US-004: one row per completed delivery attempt (ADR 0014). Owned by the dispatch module; append-only.
-- New, empty table: old code never reads it, so it is safe to run before the new worker starts.
-- The foreign key takes a brief SHARE ROW EXCLUSIVE lock on deliveries (publish waits milliseconds);
-- lock_timeout makes a blocked migration fail fast instead of queueing traffic behind it.
SET lock_timeout = '5s';

CREATE TABLE attempts (
  id                      text PRIMARY KEY CHECK (id LIKE 'att\_%'),
  project_id              text NOT NULL,
  delivery_id             text NOT NULL,
  -- deliveries.attempt_count + 1 at claim time; a crash consumes no number (ADR 0014 section 3).
  attempt_number          integer NOT NULL CHECK (attempt_number >= 1),
  -- Copied from the delivery when it was claimed (automatic, or manual after a replay in US-007).
  trigger                 text NOT NULL CHECK (trigger IN ('automatic', 'manual')),
  started_at              timestamptz NOT NULL,
  duration_ms             integer NOT NULL CHECK (duration_ms >= 0),
  -- Set when the receiver answered (any status, 3xx included); NULL for timeouts and network errors.
  response_status         smallint CHECK (response_status BETWEEN 100 AND 599),
  -- First 4 KB of the response as valid UTF-8 without NUL bytes (the worker sanitizes it).
  response_body           text CHECK (octet_length(response_body) <= 4096),
  response_body_truncated boolean NOT NULL DEFAULT false,
  error                   text CHECK (error IN ('timeout', 'connection_error', 'dns_error',
                                                'destination_blocked', 'endpoint_disabled')),
  -- The attempt list per delivery (US-006) uses this index, and it stops double-recording.
  UNIQUE (delivery_id, attempt_number),
  -- Isolation: an attempt can only belong to a delivery of the same project (architecture 7.3).
  FOREIGN KEY (delivery_id, project_id) REFERENCES deliveries (id, project_id),
  -- Exactly one of "the receiver answered" and "it did not".
  CHECK ((response_status IS NULL) <> (error IS NULL)),
  CHECK (response_body IS NULL OR response_status IS NOT NULL),
  CHECK (NOT response_body_truncated OR response_body IS NOT NULL)
);
```

**Down**

```sql
-- Destructive: deletes the attempt history. Deliveries, messages and endpoints survive.
SET lock_timeout = '5s';

DROP TABLE IF EXISTS attempts;
```

Notes:
- No extra index: `UNIQUE (delivery_id, attempt_number)` serves the attempt list and the FK lookups from
  `deliveries` deletes (US-016). Retention by age (US-016) will add `attempts (started_at)` with
  `CREATE INDEX CONCURRENTLY` in its own migration.
- Rollback order for a bad deploy: stop the new worker first (it writes `attempts`), then `migrate down`.
  The old M0 worker does not touch the queue, so it runs fine on either schema.
- `endpoint_integration_test.go` migrates all the way down; it now also passes through 0005. Check it still passes.

## 6. Signing and the outbound request

| Item | Value |
|---|---|
| Method, URL | `POST` to the endpoint's **current** URL (read after the claim) |
| `webhook-id` | message ID (`msg_...`), the same for every endpoint, retry and replay |
| `webhook-timestamp` | `started.Unix()` as decimal seconds, taken from the injected clock right before sending |
| `webhook-signature` | `v1,` + base64 (standard, padded) HMAC-SHA256 over `{id}.{ts}.{body}` |
| HMAC key | the 32 raw bytes stored sealed in `endpoints.secret_ciphertext`, opened by the endpoint module. **No base64 decoding happens in the worker:** `whsec_` + base64 is only the display form (`SigningSecret.Value()`), and `SigningSecret.Bytes()` already is the decoded key |
| Body | the stored `messages.payload` bytes, the same slice from scan to `bytes.NewReader`. Never re-marshalled |
| `content-type` | `application/json` exactly |
| `user-agent` | `Hookrelay/<version> (+https://github.com/hookrelay/hookrelay)` |
| Redirects | never followed; a 3xx is a failed attempt with its status |
| Timeout | one `context.WithTimeout(DELIVERY_TIMEOUT)` covering dial, TLS, headers and the 4 KB body read |

**Interop proof:** a test-only dependency on the Standard Webhooks reference Go library (ADR 0007; the
engineer pins the module path with `go list -m` before adding it). The E2E receiver verifies every
request with it, using the `whsec_...` string from `GET /v1/endpoints/{id}/secret`, and a copy with one
body byte flipped must fail verification.

## 7. Timing, concurrency and capacity

- **Latency budget (AC: ≤ 5 s):** publish commits → next poll ≤ 500 ms → claim + 2 lookups (~5 ms) →
  send. Expected p99 well under 1 s for a healthy receiver. The E2E test asserts < 5 s.
- **Crash recovery (AC: ≤ 60 s):** lease 30 s + poll 0.5 s = **≤ 30.5 s**. Config guarantees lease > timeout + 5 s.
- **Shutdown:** drain ≤ 25 s + completion ≤ 3 s = 28 s < Fly `kill_timeout = 30` and compose `stop_grace_period: 30s`.
- **Concurrency:** ≤ `WORKER_CONCURRENCY` attempts per process; never more leases than free slots. Two
  processes are safe because `SKIP LOCKED` makes claimers skip each other's rows, and completion is fenced.
- **Pool:** worker pool stays at 6. No connection is held during HTTP; a completion holds one for ~2 ms.
  Statement timeout 5 s still applies.
- **Queries:** per batch 3 (claim, targets, payloads), per attempt one transaction of 2 statements. Idle: 2 claims/s per worker
  on the partial `deliveries_due_idx`.
- **Memory:** ≤ 16 payloads × 256 KB = 4 MB per process in the worst case.
- **Duplicates:** only after a crash or a lease lost to a stalled worker. At-least-once, same `webhook-id`.

## 8. What each failure looks like

| Situation | Attempt row | Delivery |
|---|---|---|
| 2xx | status, body ≤ 4 KB, truncated flag, duration | `succeeded` |
| 3xx / 4xx / 5xx / 1xx final | status, body | `failed` (US-005: retry) |
| No response within timeout | `error = timeout`, status NULL | `failed` (US-005: retry) |
| DNS failure | `dns_error` | `failed` (US-005: retry) |
| Refused, reset, TLS | `connection_error` | `failed` (US-005: retry) |
| Production, host resolves to blocked IP | `destination_blocked`, no socket opened | `failed`, terminal |
| Endpoint disabled at delivery time | `endpoint_disabled`, duration 0, no request | `failed`, terminal |
| Worker SIGKILL mid-flight | none for the lost try | `pending`, reclaimed ≤ 30.5 s later |
| SIGTERM, attempt finishes within the drain | normal row | normal |
| SIGTERM, drain deadline cuts the attempt | none | `pending`, reclaimed after its lease |
| Stalled worker lost its lease | its result is dropped (`lease_lost` log) | whatever the reclaiming worker recorded |
| Target missing / secret unreadable / payload missing | none | stays leased, retried after the lease, `error` log |
| Postgres down | none | the loop backs off (≤ 5 s) and keeps running; health turns 503 after 30 s without a claim |

## 9. Security

- **SSRF:** dial-time guard in production (resolve, check every address, dial the checked IP, `Control` re-check),
  no redirects, no proxy, TLS ≥ 1.2, allowlisted client only for allowlisted URLs (ADR 0003). The registration check stays.
- **Secrets:** decrypted only inside the endpoint module, carried as `SigningKey` that redacts itself in every
  format; never logged. The signature header is not logged either.
- **Logs never contain:** payloads, response bodies, URLs (customers put tokens in query strings; log `endpoint_id`),
  signatures, secrets. A test captures the log buffer of an E2E run and asserts none of them appear.
- **Response bodies** are stored (4 KB) and will be shown in the dashboard as text (US-006/008), never as HTML.
- **Resource limits:** 16 KB response headers, 4 KB body read, 10 s per attempt, bounded concurrency.
- **Isolation:** composite FKs: an attempt cannot point to another project's delivery, a delivery cannot pair
  projects. The worker is system-level by design and reads no tenant input other than stored rows.

## 12. Risks and limits

- **Poison job:** a delivery that crashes the process every time is reclaimed every 30 s forever (the claim does not
  count tries; ADR 0014). The runner recovers panics, so this needs an out-of-process crash (OOM).
- **SIGKILLed attempts leave no row**; the receiver may have processed them (open question Q14).
- **Disable race:** a disable within milliseconds of the target read still sends once.
- **FIFO across projects:** one project's burst delays others (architecture §10, P1/P2 fairness).
- **Process tests need Linux** (`syscall.Kill`); on Windows they are skipped and the in-process lease tests cover the logic.
- **Reference library module path** is not pinned yet; if it is awkward to vendor, the interop test falls back to a
  second, independent verifier in the test (as `demoreceiver.Verify` will be in US-010) plus the published vector.
- **Until US-005 ships,** any non-2xx is final. Do not deploy US-004 publicly without US-005 if a flaky receiver would mislead reviewers.
