## 3. SSRF rule set (`library/netguard`, registration only)

Registration does DNS only and never makes an HTTP request to the URL.

**All modes (syntax, in `entity.NewEndpoint`):** absolute URL; scheme `http` or `https`; host present;
no userinfo; at most 2048 characters. Failure returns `400`, field `url`.

**Development mode:** syntax only. `http://localhost:9000/hook` is accepted.

**Production mode (`Policy.Check`), in this order, first failure wins:**

1. Allowlist: `OUTBOUND_ALLOWLIST` entries match exact scheme, host and port plus a path prefix that
   ends on a segment boundary. A URL with a dot segment (`..`, `%2e`) never matches. A match skips the
   remaining rules. With `OUTBOUND_ALLOWLIST_ONLY=true`, anything else is rejected.
2. Scheme must be `https`.
3. Normalize the host: lowercase, strip one trailing dot (so `localhost.` cannot bypass rule 4). A
   non-ASCII host is rejected; internationalized names must be sent as punycode.
4. Name deny-list: `localhost`, `*.localhost`, `*.internal`, `*.local`.
5. Numeric-looking hosts: if the last label is all digits or starts with `0x` and the host is not a
   valid IP literal, reject it. This stops `2130706433`, `0x7f.0.0.1` and `127.1`, which some resolvers
   read as loopback.
6. **Literal IP:** parse with `net/netip`; reject any zone; **call `Unmap()` so IPv4-mapped IPv6
   (`::ffff:127.0.0.1`, `::ffff:7f00:1`) is judged as IPv4**; check the ranges.
7. **Hostname:** resolve with `LookupNetIP` (injected resolver, 2 s timeout). **Every** returned
   address, unmapped first, must be public. One blocked address rejects the URL.

**Blocked ranges:** the ADR 0003 list plus `::/96` (IPv4-compatible), `2002::/16` (6to4), `2001::/32`
(Teredo), `64:ff9b:1::/48` (local NAT64), `fec0::/10` (site-local) and `192.88.99.0/24`. Each of the
IPv6 additions can embed or reach a private address.

**DNS failure fails closed.** NXDOMAIN, an empty answer, SERVFAIL and a timeout all return `400`,
field `url`, "host could not be resolved". It is not a `5xx`, and nothing is stored.

**Error text never contains a resolved IP**, so the API cannot be used to read DNS answers.

**Port shape:** `URLPolicy.Check(ctx, rawURL) error` uses only stdlib types, so `*netguard.Policy`
satisfies it directly. Any non-nil error means the URL is rejected, and its text is safe to show.
The use case converts it to `ValidationError{Field: "url"}`.

**Delivery time belongs to US-004.** Registration checks cannot stop DNS changing later. The guarded
`DialContext` ("the IP we check is the IP we dial"), redirect refusal and `destination_blocked` are
built there, in the same package. US-002 must not claim that protection.

## 4. Data and consistency

**Table:** see migration 0003. Keyset order is `(created_at DESC, id DESC)` per project, served by
`endpoints_project_created_idx`. The same index covers the limit count.

**Endpoint limit, race-safe.** `CreateEndpoint` runs these as separate statements in one transaction:

1. `SELECT id FROM projects WHERE id = $1 FOR NO KEY UPDATE`
2. `SELECT count(*) FROM endpoints WHERE project_id = $1`; at or above the limit returns `ErrLimitReached`
3. `INSERT`

Why this design (it replaces the advisory lock in the earlier architecture draft):
- **Separate statements are required.** Under `READ COMMITTED` each statement gets its own snapshot, so
  the count taken after the lock sees the winner's commit. One statement with a locking CTE keeps the
  snapshot from before the wait and would still overshoot the limit.
- **`FOR NO KEY UPDATE`, not `FOR UPDATE`.** It conflicts with itself, so creates in one project
  serialize, but not with the `FOR KEY SHARE` lock that foreign-key inserts take. Publishing is not blocked.
- A row lock has no hash collisions between projects, and shows up plainly in `pg_locks`.
- A trigger or partial index cannot read the configurable limit.
- DNS and encryption happen **before** the transaction, so the lock is held for milliseconds.

**PATCH concurrency:** one `UPDATE ... SET url = COALESCE($3, url), ... WHERE id AND project_id RETURNING ...`.
Last writer wins per field, never across fields. The response comes from `RETURNING`.

**Secrets (ADR 0004).** 32 random bytes. `SecretCipher` is declared in `endpoint/domain/repository` and
called by `data/repository`. Sealed as `nonce || ciphertext || tag` with AAD = endpoint ID.
`Get` and `List` never select the ciphertext. `secret_key_version` is derived: 1 + (first two SHA-256
bytes of the key, mod 32767). This needs no operator bookkeeping. `secretbox.New` fails startup if the
current and previous keys derive the same version.

**Timestamps:** truncate to microseconds in UTC before they enter the entity. Postgres stores
microseconds, so otherwise a keyset cursor and the create response disagree with the stored row.

**N+1:** none; each list is one query. **Indexes on the migration:** the table is new, so no
`CONCURRENTLY` is needed.

## 5. PATCH semantics

| Input | Result |
|---|---|
| Field absent | Unchanged |
| Field present with a valid value | Validated and applied; `""` clears `description` |
| Field is `null` | `400 validation_error`, `field` = that field. Never read as absent |
| `{}` | `400 validation_error`, `field: "body"` |
| Unknown field, or `signing_secret` | `400` (strict decoder) |
| `url` present | Full syntax and SSRF checks, even if it equals the stored URL |
| `url` absent (for example only `enabled`) | No DNS lookup, so disabling works when DNS is broken |
| Valid values identical to stored ones | `200`, `updated_at` changes |
| Foreign or unknown ID | `404`, checked before URL policy |

`*string` cannot tell absent from `null`, so the DTOs use a small generic `dto.Field[T]` recording
`Present` and `Null`. `description` on create uses it too. **This replaces "null treated as omitted"**
in architecture 4.3: the contract marks no field nullable, and a silent no-op hides client bugs.

## 6. Plan by layer (paths under `internal/`)

### Libraries (Step 1)
- `library/secretbox`: `Options{Key, PreviousKey}`, `New`, `Seal`, `Open`.
- `library/netguard`: `ranges.go`, `policy.go`, `resolver.go`.
- `library/postgres`: `tx.go`: `TxManager.WithinTx`, `Executor(ctx, pool)`.
- `platform/httpx/cursor.go`: encode and decode `v1|<RFC3339Nano>|<id>`, `ParseLimit` (default 20, 1-100).

### Domain: `endpoint/domain`
- `entity/`: `endpoint.go` (`Endpoint` has **no secret field**; `NewEndpoint`, `ApplyPatch`), `patch.go`,
  `signing_secret.go` (`whsec_` rendering; `String`, `Format` and `LogValue` redact, `Value()` reveals).
- `errors/`: `sentinel.go` (`ErrNotFound`, `ErrInvalid`, `ErrLimitReached`), `validation_error.go`,
  `limit_reached_error.go` (carries the limit, unwraps to `ErrLimitReached`).
- `repository/`, one port per file:
  - `EndpointRepository{Create, Get, List, UpdateFields, CountForUpdate}`
  - `SecretReader{GetSecret}`
  - `SecretCipher{Seal, Open}`
  - `URLPolicy{Check}`

### Use cases: `endpoint/domain/usecase`, one per endpoint
Ports, one per file: `Clock`, `IDGenerator`, `RandomSource`, `TxManager`.

| Use case | Route | Flow |
|---|---|---|
| `CreateEndpoint` | `POST /v1/endpoints` | entity → `URLPolicy` → random secret → tx{`CountForUpdate`, limit guard, `Create`} |
| `ListEndpoints` | `GET /v1/endpoints` | `List` limit+1 → trim → next cursor |
| `GetEndpoint` | `GET /v1/endpoints/{id}` | `Get` |
| `GetEndpointSecret` | `GET /v1/endpoints/{id}/secret` | `GetSecret` |
| `UpdateEndpoint` | `PATCH /v1/endpoints/{id}` | `Get` → `ApplyPatch` → `URLPolicy` if `url` present → `UpdateFields` |

### Data: `endpoint/data`
- `model/endpoint.go`.
- `source/endpoint_persistent.go`, `errors.go`, `db.go`: all SQL, through `postgres.Executor` so calls join the transaction.
- `repository/endpoint_repository_impl.go`, `secret_reader_impl.go`, `endpoint_mapper.go`: mapping, sealing, error translation.

### Delivery: `endpoint/delivery`
- `dto/`: one file per use case, plus `field.go`.
- `presenter/http/` (`httppresenter`): one handler per file, `routes.go` (all wrapped with `authed`), `errors.go`, `mapper.go`.
- `errors.go` maps `LimitReachedError` to `409 conflict`, "endpoint limit of N per project reached", and malformed IDs behave as `404`.
- `Cache-Control: no-store` on create and on the secret route. List and get DTOs have no secret field.

### Wiring: `wire/endpoint.go`
`EndpointSet` holds all `wire.Bind`s to the endpoint ports (deviation, see the note below; `Clock`, `IDGenerator`, `RandomSource`,
`TxManager`, `URLPolicy`, `SecretCipher`). `router.go` receives the `RequireProject` guard as a named
function type from `ProjectSet`, so `endpoint` never imports `project`. `options.go` maps
`IsProduction`, the allowlist settings, encryption keys and `MaxEndpointsPerProject`.

**Implemented differently:** the clock, ID, randomness and transaction ports are satisfied by small
`Provide...` functions, not `wire.Bind`. A Bind needs the concrete provider in the same set, and
two module sets cannot both include the shared `CoreSet` (Wire reports duplicate bindings).

## 8. Risks and limits

- Repeated failed registrations trigger DNS lookups with no rate limit until US-012.
- A transient DNS failure blocks registration with `400`. The client may retry (architecture Q8).
- Key loss makes secrets unrecoverable (ADR 0004). Secret rotation is US-011.
- A create waits on the project row lock while another create of the same project runs. The lock is held
  for milliseconds, but a stuck holder blocks creates of that project until the 5 s `statement_timeout`.
  A `SET LOCAL lock_timeout` on the create transaction is a possible hardening.
- PATCH never re-seals a secret, so rows keep the key version they were created with. See the key
  rotation note in ADR 0004: a re-seal job (future work) must run before `SECRET_ENCRYPTION_KEY_PREVIOUS` is dropped.
