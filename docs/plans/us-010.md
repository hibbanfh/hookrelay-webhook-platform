## 2. Request flow

```
POST /demo/receiver/{project_id}?fail_first=N        (public; registered only if DEMO_RECEIVER_ENABLED)
handler: IsProjectID(path)             else 404 "demo receiver not found"   (no use case call)
         fail_first: absent → 0, int, once   else 400 field fail_first
         body = httpx.ReadBody(r)       > MAX_BODY_BYTES → 413 (never parsed as JSON)
         headers: exactly one value each of webhook-id / webhook-timestamp / webhook-signature, else ""
ReceiveWebhook.Execute:
  1. NewFailurePlan(N)                  N ∉ [0,10] → ValidationError{fail_first} → 400
  2. ParseSignedWebhook(headers, body)  malformed → ErrInvalidSignature → 401
  3. wh.IsFresh(clock.Now())            |now − ts| > 5 min → ErrStaleTimestamp → 401
  4. secrets.DemoSecrets(projectID)     ≤ 20 candidates (adapter → endpoint.ListDemoSigningSecrets)
  5. first candidate whose signer.Sign(key, id, ts, body) ∈ wh.Signatures (hmac.Equal)
                                        none (incl. unknown project) → ErrInvalidSignature → 401
  6. hits.Increment({endpoint, id}, now, now − 7d) → n
  7. plan.ShouldFail(n)                 → SimulatedFailure{n, N} → 500 simulated_failure
  8. Receipt{endpoint, id, n, N}        → 200 DemoReceiverResult
```

Queries per request: 1 (unknown project, or a request that fails before step 4: 0), plus 1 upsert and 1 bounded sweep once the
signature is valid. No N+1: the candidates come from a single statement, and the HMACs are CPU only.

### Step 4: `internal/demoreceiver/data` + migration (integration tests, `-tags integration`)

`migrations/0006_demo_receiver_hits.up.sql`:

```sql
-- US-010: per (endpoint, webhook-id) request counter of the built-in demo receiver (ADR 0017).
-- Owned by the demoreceiver module. New, empty table: old code never reads it, so it is safe before the new API starts.
-- The foreign key takes a brief SHARE ROW EXCLUSIVE lock on endpoints; lock_timeout makes a blocked migration fail fast.
SET lock_timeout = '5s';

CREATE TABLE demo_receiver_hits (
  -- CASCADE, unlike everywhere else: disposable test state must never block deleting an endpoint.
  endpoint_id   text NOT NULL REFERENCES endpoints (id) ON DELETE CASCADE,
  -- The Standard Webhooks id as received (Hookrelay sends the message ID); only stored after a valid signature.
  webhook_id    text NOT NULL CHECK (char_length(webhook_id) BETWEEN 1 AND 255),
  hits          integer NOT NULL CHECK (hits >= 1),
  first_seen_at timestamptz NOT NULL,
  last_seen_at  timestamptz NOT NULL,
  PRIMARY KEY (endpoint_id, webhook_id),
  CHECK (last_seen_at >= first_seen_at)
);
-- The write-path sweep finds expired rows oldest first (ADR 0017 section 1).
CREATE INDEX demo_receiver_hits_last_seen_idx ON demo_receiver_hits (last_seen_at);
```

1. Migration up → down → up is clean (extend the existing migration test). `\d demo_receiver_hits` has the PK, the FK

2. First hit → 1; then 2, 3. Another `webhook_id` on the same endpoint → 1. Same `webhook_id` on a second endpoint → 1.
3. **Concurrency:** 50 goroutines × 1 increment on one key, each on its own pool connection, released together →
   results are exactly `{1..50}` and the row says 50 (`-race`).

6. **Sweep vs. hit race:** goroutine A refreshes an expired key while B (another key) sweeps → the refreshed row
   survives with `hits = 1` (repeat 100×).

## 5. Security, limits and operability

- **Auth:** public route; the signature over id, timestamp and body is the credential. Every unauthenticated failure
  is a `401` with one of two fixed messages; unknown project = wrong signature (ADR 0017 §3).
- **Abuse bound without rate limits:** ≤ 1 indexed read, ≤ 20 AES-GCM opens, ≤ 20 HMACs over ≤ 256 KB, no write. The
  counter writes only after a valid signature, and the 7-day write-path sweep bounds it. Rate limits are US-012.
- **SSRF:** the allowlist is exactly `DEMO_RECEIVER_BASE_URL` (or empty), validated at startup. The same match is used
  at registration and for client choice at send time. The allowlisted dialer only reaches that host and port, and
  redirects are off. Other paths and ports on the same private host go through the guarded dialer and are blocked in
  production.
- **Logs:** the access line has `route`, `status`, `duration_ms`. Simulated failures are not error logs. Never log the
  body, the signature header or the secrets (`SigningKey` redacts itself).
- **Response bodies are stored on the attempt** (first 4 KB): the 200/500 bodies above contain only IDs and counters.
- **Pool:** the receiver shares the API pool (max 10). Each verified hit is one short autocommit upsert.

## 8. Risks and limits

- **The sweep is a `DELETE ... USING (SELECT ... FOR UPDATE SKIP LOCKED)`.** It runs as its own statement after the
  upsert (the fallback this plan first kept in reserve became the design, because a data-modifying CTE next to the
  upsert leaves the order of the parts to the planner). Repository tests 5 and 6 must keep passing. Correctness of
  the count does not depend on the sweep.
- **Seven-day reset:** a replay of a `fail_first` endpoint's message more than 7 days after its last hit fails again
  (PM Q29).
- **URL spelling:** only `demo_receiver_url` verbatim (plus `?query`) is a demo endpoint. Hand-typed variants get `401`.
- **Base URL change:** changing `DEMO_RECEIVER_BASE_URL` orphans existing demo endpoints (they now `401` or are
  blocked). Re-running the seed adds new ones next to them, and the old ones count toward the 20-endpoint limit until
  a demo reset (architecture Q4).
- **Hairpin on Fly:** with the default public base URL, the worker reaches the receiver through Fly's edge proxy (a few
  ms, TLS). Correct and simple. A private-network base URL is possible but not needed.
- **Timing:** an unknown project answers slightly faster than a known one (no decrypt/HMAC). That is acceptable,
  because project IDs are not secret (ADR 0017 §3).
- **Test flakiness:** E1 relies on the `1s,2s` schedule with ±10% jitter; poll the attempts API with a 10 s deadline
  and a 50 ms tick. Do not assert exact gaps.
